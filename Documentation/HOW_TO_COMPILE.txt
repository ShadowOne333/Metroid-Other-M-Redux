METROID: OTHER M — CUTSCENE SUIT MODEL PATCH
How to Compile (In-Place, Single-Word Version)
================================================

This guide covers compiling cutscene_suit_model_patch.s and applying it
to a vanilla game.rel. The patch makes NO change to the file's size,
requires NO linker script and NO Python script — only a PowerPC
assembler, plus one fixed-offset byte copy at the end.

Files you need:
  - cutscene_suit_model_patch.s   (the patch source)
  - game-original.rel             (a clean, unmodified game.rel)


------------------------------------------------------------------------
STEP 0 — Install the toolchain (one-time setup)
------------------------------------------------------------------------
You need a PowerPC assembler for big-endian 32-bit PowerPC (the Wii's
Broadway CPU). Either of these works identically for this patch:

  Option A — devkitPPC (standard Wii/GameCube homebrew toolchain)
    Binaries are typically named:
        powerpc-eabi-as
        powerpc-eabi-objcopy

  Option B — plain GNU binutils, PowerPC Linux target
    On Ubuntu/Debian:
        sudo apt-get install binutils-powerpc-linux-gnu
    Binaries:
        powerpc-linux-gnu-as
        powerpc-linux-gnu-objcopy

The rest of this guide uses the binutils names; substitute the
devkitPPC names if that's what you have.


------------------------------------------------------------------------
STEP 1 — Assemble the source into an object file
------------------------------------------------------------------------
    powerpc-linux-gnu-as -mbig -o cave.o cutscene_suit_model_patch.s

  -mbig      encode big-endian, matching the Wii's CPU (set explicitly
             because some toolchains default to little-endian)
  -o cave.o  output object file

If this fails, check the source wasn't altered — in particular the
leading '%' on register names (%r5, %r6, %r7, %r3) must be present.

cave.o is an ELF object: it still has headers around the instructions,
so it is not yet the raw machine code we need.


------------------------------------------------------------------------
STEP 2 — Extract the raw machine code
------------------------------------------------------------------------
    powerpc-linux-gnu-objcopy -O binary cave.o cave.bin

This strips the ELF wrapper, leaving only the instruction bytes.

Verify cave.bin is exactly 200 bytes (50 instructions x 4 bytes):

    Linux/macOS:          wc -c cave.bin       (should print 200)
    Windows PowerShell:   (Get-Item cave.bin).Length

If it is not exactly 200 bytes, the NOP padding count at the bottom of
the .s file was changed. Do not continue until it is fixed (12 real
instructions + 38 NOPs = 50 instructions = 200 bytes).


------------------------------------------------------------------------
STEP 3 — Splice the 200 bytes into game.rel
------------------------------------------------------------------------
This is the only step that touches game.rel. It overwrites file offset
0xCADC0 (decimal 51648) with the 200 bytes of cave.bin and nothing
else — no header fields, section table, or relocation data. Work on a
copy of game-original.rel.

  Linux/macOS:
    cp game-original.rel game.rel
    dd if=cave.bin of=game.rel bs=1 seek=51648 conv=notrunc

  Windows PowerShell:
    Copy-Item game-original.rel game.rel
    $bytes = [System.IO.File]::ReadAllBytes("cave.bin")
    $fs = [System.IO.File]::Open("game.rel", 'Open', 'Write')
    $fs.Seek(51648, 'Begin') | Out-Null
    $fs.Write($bytes, 0, $bytes.Length)
    $fs.Close()

dd options:
  if=cave.bin    the 200 bytes to write
  of=game.rel    file being modified in place
  bs=1           1-byte blocks, so `seek` counts bytes
  seek=51648     skip this many bytes before writing (0xCADC0)
  conv=notrunc   REQUIRED. Without it dd truncates game.rel to the 200
                 written bytes instead of overwriting in place.

game.rel's size must be identical before and after (9,213,360 bytes for
the build used in development). If it changed, conv=notrunc was
probably omitted or the wrong file was targeted.


------------------------------------------------------------------------
STEP 4 (optional) — Verify the result
------------------------------------------------------------------------
With Python available, this confirms exactly the intended bytes changed:

    python3 -c "
o = open('game-original.rel','rb').read()
n = open('game.rel','rb').read()
assert len(o) == len(n), 'FILE SIZE CHANGED'
d = [i for i in range(len(o)) if o[i] != n[i]]
print('differing bytes:', len(d), hex(min(d)), '-', hex(max(d)))
assert min(d) >= 0xCADC0 and max(d) < 0xCAE88, 'unexpected region changed'
print('OK')
"

Expected output:
    differing bytes: 138 0xcadc0 - 0xcae87
    OK

(138 rather than 200 because some of the 200 bytes happen to match what
was already there, e.g. the NOP padding overlapping existing NOPs or
identical bytes. That is normal.)


------------------------------------------------------------------------
WHAT THE PATCH DOES
------------------------------------------------------------------------
It replaces the vanilla room-ID decision tree at 0xCADC0-0xCAE87 with a
routine that reads the player's persistent suit bits and picks the
cutscene model directly. The bits live in one word at runtime address
0x80CA4E20 (gear_struct+0x00):

    bit 0 (0x1)  Power       0001 = 1
    bit 1 (0x2)  Varia       0011 = 3
    bit 2 (0x4)  Gravity     0111 = 7

    bit 2 set  -> model 254 (Gravity)    [tested first]
    bit 1 set  -> model 253 (Barrier)
    otherwise  -> model 252 (Power)

Only these bits are examined. Other bits in the word (other items) are
ignored, so they can change freely.

Why the address is hardcoded: BSS's runtime address depends on the
module's total file size. This patch changes no sizes, so BSS lands
exactly where vanilla puts it (0x80CA4E20 for gear_struct). The header
and section table are byte-identical to vanilla, which is the proof. If
this patch is ever combined with something that changes game.rel's
total size, re-confirm the address with a live memory dump first.


------------------------------------------------------------------------
TROUBLESHOOTING
------------------------------------------------------------------------
"unrecognized option '-mbig'"
  Your assembler may already default to big-endian or name the flag
  differently. Try without -mbig, then disassemble cave.bin and compare
  with the expected first instruction `lis r5, 0x80CA` (bytes
  3C A0 80 CA). If the bytes are reversed, you need an explicit
  big-endian option (see `as --help`).

cave.bin is not 200 bytes
  The .rept 38 / nop / .endr block was altered.

Wrong suit model in game / crash
  - Confirm you patched a clean game-original.rel and the size is
    unchanged.
  - If another change to game.rel altered its size, BSS may have moved;
    check gear_struct in Dolphin's memory view against vanilla.
  - Power models showing as Barrier: bit 1 of 0x80CA4E20 may be set
    earlier than expected in your save; check the live value.
