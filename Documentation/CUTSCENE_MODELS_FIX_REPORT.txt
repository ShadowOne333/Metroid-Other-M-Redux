METROID: OTHER M — CUTSCENE SUIT MODEL FIX
Fix Report (Final, In-Place, Single-Word Version)
===================================================

PROBLEM
-------
Cutscene-Samus always displayed model 253 (BARRIER) after the Varia Suit
was obtained, even once the Gravity Suit was acquired later. The base
game had no distinct Gravity cutscene appearance (model 254 exists, but
nothing ever selected it), so cutscenes never reflected suit progression
past Barrier.


ROOT CAUSE
----------
The cutscene model-selection function (0xCADAC) chose a model using a
coarse room/area-state variable and a decision tree that only
distinguished "Barrier-appropriate room" from "everything else". That
room variable does not change between Barrier-era and Gravity-era areas,
so nothing in the function could tell the two apart: it hardcoded model
253 whenever a suit-relevant cutscene was detected.


THE FIX
-------
The entire room-ID decision tree (0xCADC0 through 0xCAE87, 200 bytes) is
replaced with a small routine that ignores room state and reads the
player's persistent suit bits, a single word at runtime address
0x80CA4E20 (the start of the gear structure that the well-known
"All Gear" cheat also targets):

    bit 0 (0x1)  Power      0001 = 1
    bit 1 (0x2)  Varia      0011 = 3
    bit 2 (0x4)  Gravity    0111 = 7

Decision logic:

    bit 2 set  ->  model 254 (GRAVITY)     [tested first]
    bit 1 set  ->  model 253 (BARRIER)
    otherwise  ->  model 252 (POWER)

Only these three bits are examined; the other bits in the word (other
items) change freely and are ignored. Testing Gravity first also covers
cutscene states where Gravity is set without Varia (for example a
low nibble of 5), which resolve to Gravity.

This replaces two earlier mechanisms:
  - A flag read from gear_struct+0x08. Further testing showed that word
    holds missile-tank data; its bit 0 matching the Gravity pickup was a
    coincidence and could misfire in other saves.
  - A special case for the value 0x15, added for cutscene dm65_02 when
    jumped to directly from the Theater menu. That value already has bit
    2 set, so the normal Gravity test handles it and the special case is
    no longer needed.

Because the routine decides all three outcomes itself, it does not
depend on the old room-based tree or on the separate logic that used to
handle "everything else" cutscenes.


CHANGES TO THE FILE
-------------------
A pure in-place overwrite. The file's size and layout are unchanged:

  - 200 bytes at file offset 0xCADC0 (the vanilla room-ID tree) are
    replaced with the new routine (12 instructions) followed by no-op
    padding to match the original tree's length.
  - Nothing else changes: no section grows, no pointers move, no header
    field changes, no relocation entries are added.

Because the file's total size is unchanged, the game's save-state memory
lands at exactly the address it has in an unmodified game, so the
routine can read 0x80CA4E20 directly instead of going through the REL
relocation mechanism. This is only safe because of the size guarantee.


VERIFICATION
------------
  - The replaced region was checked beforehand and contains no
    relocations, so overwriting it cannot corrupt anything else.
  - The routine was disassembled and every branch target confirmed.
  - The patched file was diffed against a clean vanilla file: 138 bytes
    differ, all inside 0xCADC0-0xCAE87. The header, section table and
    all code from 0xCAE88 onward are byte-identical to vanilla.
  - A truth table over every value observed in testing gives the
    expected models: 0x8911, 0xC931, 0x11, 0x31 -> 252 (Power);
    0xC933, 0xFEFF3, 0x13 -> 253 (Barrier); 0xFEFF7, 0xFEF95, 0x15, 0x1D
    -> 254 (Gravity).
  - NOT YET TESTED IN-GAME: this exact build. The earlier build with
    the +0x08 and 0x15 checks was tested across Power/Barrier/Gravity
    cutscenes, reloads, and dm65_02. This build should be run through
    the same battery before it is treated as final.
